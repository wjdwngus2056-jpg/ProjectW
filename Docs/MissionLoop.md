# MissionLoop: 소방서 출동과 복귀

검증일: 2026-11-25 · 기준: `origin/develop`의 `b19f3c2` · UE 5.8.3 / 싱글플레이

기존 `Mission_Test` 패널과 출동 포탈, 미션 정의 DataTable, 두 프로토타입 맵을 연결한다. 개발용 큐브 목표 1개를 상호작용으로 완료하고 결과에서 소방서로 복귀한 뒤 같은 미션에 새로 출동할 수 있다. 실제 구조·처치·진압, 사망 실패, 보상·영구 성장, 미션 안에서 즉시 재시작은 후속 범위다.

`AWMissionLoopHUD`의 목표·결과 표시와 결과 화면의 즉시 복귀 버튼은 **테스트용 임시 UI**다. 이 브랜치에서는 목표 보고·결과 확정·맵 왕복과 재출동을 확인한다. 개발용 단일 목표가 바로 성공 결과를 내고 버튼으로 즉시 돌아오는 흐름은 실제 필수 목표 완료·탈출 수락을 구현한 것이 아니다. 화면 첫 줄의 `[테스트용 임시 UI]` 표시도 같은 범위를 알린다. 정식 UI 작업에서 표시·입력·화면 전환을 교체한다.

## 실행

`L_Prototype_FireStation`에서 플레이한다. 기존 이동 입력으로 미션 패널에 접근해 상호작용한 뒤 출동 포탈을 사용한다. HUD가 입력 에셋에서 상호작용 키를 조회해 표시한다. 미션에서는 앞쪽 개발용 큐브에 접근해 같은 상호작용을 사용한다. 결과 화면에서 **R 또는 복귀 영역 클릭**으로 소방서에 돌아간다. 패널 선택과 출동을 다시 수행하면 새 시도가 시작된다.

사용자 승인에 따라 `GameDefaultMap`과 `EditorStartupMap` 모두 소방서로 설정했다. 전자는 실행 인자가 없는 게임의 시작 맵, 후자는 에디터 최초 오픈 맵이다. 기존 로컬 변경의 두 줄을 그대로 포함했다. 두 맵은 `DefaultGame.ini`의 `MapsToCook`에 명시했다.

## 책임과 수명

| 소유자 | 역할 |
| --- | --- |
| `AWFireStationGameMode` | 미션 선택·출동 재검증·중복 출동 차단, 전달받은 이전 결과 표시용 보관 |
| `AWMissionGameMode` | `MissionId` 수신, 정의·목적지·목표 배치 검증, 완료 요청 검증, 결과 확정, 복귀 |
| `AWMissionGameState` | 시도 ID, 미션 ID, 진행 상태, 완료 수량, 확정 결과·이동 오류의 조회 원본 |
| `AWDevelopmentMissionObjective` | C++ `IWInteractable` 경로로 완료 요청 전달. 별도 진행 상태는 소유하지 않음 |
| `UWMissionResultTransfer` | 확정 결과 한 건의 값 복사본을 맵 사이에 전달. 소방서에서 한 번 소비하면 비움 |
| `AWMissionLoopHUD` | 테스트용 임시 UI. 현재 상태 조회·상호작용 안내·결과 표시, 즉시 복귀 요청 전달 |

새 시도의 상태는 새 미션 월드에만 생성한다. GameInstanceSubsystem에는 진행 중 목표나 Actor 참조를 저장하지 않는다. 소스의 기존 `Mission/` 경로를 유지하고 새 최상위 폴더나 모듈은 추가하지 않았다. Core 컨트롤러에 미션 규칙을 넣지 않았다. GAS·RPC·복제·온라인 기능도 추가하지 않았다.

`FWMissionDefinition.DevelopmentObjectiveId`는 이번 왕복 검증용 정의다. 기존 DataTable을 유지하고 목표가 정확히 하나이며 ID가 일치할 때만 시작한다. 개발용 목표는 Shipping에서 진행을 시작하지 않는다. 후속 실제 목표 구현 때 이 개발용 완료 경로를 교체해야 한다.

## HUD 교체 계약과 후속 연결 — 2026-11-27

현재 HUD는 매번 `AWMissionGameState`의 조회 API에서 진행·결과·이동 오류를 읽는다. HUD에 목표 수량이나 확정 결과를 별도로 소유하지 않는다. R과 클릭은 모두 `AWMissionGameMode::TryReturnToStation`에 소유 컨트롤러를 전달한다. 결과·요청자·중복 검증과 상태 변경·맵 이동은 GameMode가 처리한다.

미션 GameMode 생성자의 기본 HUD는 임시 HUD로 유지한다. `InitGame`은 유효한 `HUDClass` 설정을 보존하고, 미지정 또는 추상 클래스일 때만 임시 HUD로 대체한다. 현재 오류 결과의 복귀 경로는 유지한다. 교체 HUD는 성공뿐 아니라 초기화 실패의 사유와 복귀 요청도 제공해야 한다. Blueprint HUD도 기존 GameState 조회 함수와 새로 노출한 `CanReturnToStation`(조회), `TryReturnToStation`(요청)을 사용할 수 있다. 복귀 요청의 `true`는 이동 완료가 아닌 수락을 뜻한다. 콘텐츠 초기 구성용 `ConfigureMissionLoop.py`는 임시 HUD를 명시적으로 지정하므로 교체 HUD 설정 후 일반 실행 용도로 재실행하지 않는다.

화면 표시는 별도 첫 줄에 두고 본문을 한 행(30px) 내린다. 패널 높이도 같은 만큼 늘리며 복귀 버튼과 `AddHitBox`는 동일한 새 좌표를 사용한다. 임시 UI 표시·결과 안내·클릭 영역의 배치가 겹치지 않도록 구성했다. 실제 화면 확인은 사용자 플레이 결과로 확정한다.

현재 역할과 다음 연결점은 다음과 같다. 이번 변경은 새 탈출 상태·Actor·시퀀스나 실제 목표 콘텐츠를 구현하지 않는다.

| 경계 | 현재 구현 | 후속 연결점 |
| --- | --- | --- |
| 미션 초기화 | `InitializeMission`: 정의·맵·개발용 목표 검증 | 정의에 선택 진입 시퀀스를 지정하고 GameMode가 종료 후 조작·목표 진행을 연다 |
| 목표 완료 보고 | `TryCompleteDevelopmentObjective`: 보고 재검증 후 1/1 기록 | 구조·진압 등 필수 목표와 등장한 보스의 처치 조건을 추적한다. 모두 완료되면 탈출을 열며 목표 Actor가 HUD나 이동을 직접 호출하지 않는다 |
| 결과 확정 | `FinalizeResult`: 중복을 막고 결과 한 번 확정 | 필수 목표 완료와 실제 탈출 수락을 분리한다. 살아 있는 플레이어의 유효한 탈출을 GameMode가 수락할 때 성공을 확정한다 |
| 소방서 이동 | `TryReturnToStation`: 결과·요청자·목적지 검증 후 즉시 이동 | 선택 귀환 전 시퀀스를 GameMode가 관리하고 완료·중단 후 이동한다. 결과 전달 경로는 재사용한다 |

진입·귀환 전 연출은 미지정·재생 불가일 때 다음 단계로 이어지고, 중단·중복·이전 시도의 콜백으로 상태 전환과 이동을 반복하지 않게 연결한다. 현재 개발용 목표가 보고 직후 `FinalizeResult`를 호출하는 부분과 결과 화면의 즉시 복귀는 그 후속 연결 전까지 왕복을 유지하는 **임시 경로**다. 플레이어·몬스터 계열의 부모/컴포넌트 구성과 공통 스킬 실행·몬스터 룬 인벤토리 기준은 해당 도메인을 변경하는 다음 작업에서 적용한다.

## 오류·중복 처리

- 없는·누락된·형식이 잘못된 `MissionId`, 잘못된 테이블·목적지·목표 배치는 진행 대신 사유가 있는 실패 결과로 연결한다. 복귀 UI는 유지한다.
- 등록된 목표와 현재 플레이어·월드·거리·진행 상태를 다시 검사한다. 완료 이후 같은 보고는 거부한다.
- 결과는 한 번만 확정한다. 결과 이후 새 스킬 요청과 캐릭터 입력을 차단하고 이동을 멈추며 HUD의 복귀 입력은 유지한다.
- 복귀 요청 이후에는 중복 복귀를 거부한다. 맵 누락은 요청 전 오류를 표시하고, 엔진 이동 실패 알림은 잠금을 해제해 재시도할 수 있게 한다.
- 미션 안의 기존 직접 이동 포탈도 확정 결과와 GameMode의 복귀 검증을 거친다. 미션 바깥의 일반 포탈 경로는 유지한다.

## 지침 반영 확인 — 2026-11-27

변경 범위는 임시 UI 표시·주석·HUD 설정 보존과 Blueprint 조회/요청 노출, 이 작업 기록이다. 미션 초기화·목표 보고·결과 확정·이동의 기존 경계와 왕복 동작은 유지한다. 이번 변경에 자동화 테스트 추가·실행, 쿠킹·패키징을 포함하지 않는다. 필요한 에디터 빌드 후 플레이 창 하나에서 사용자의 직접 결과를 기다리며, 이전 검증 수치를 이번 수정의 재검증 결과로 간주하지 않는다.

`ProjectWEditor Win64 Development` 빌드는 통과했다(`Saved/Logs/MissionLoopEditorBuild.log`). 1280×720 기준 임시 표시 줄은 Y=26, 결과의 복귀 버튼·히트박스는 Y=188~236으로 분리되고, 안내도 별도 행을 사용함을 코드에서 확인했다. 직접 테스트용 플레이 창 1회 실행 요청은 거절되어 열지 않았으며, 추가 실행 없이 직접 플레이 미실행으로 기록한다. 화면 배치·왕복의 수동 확인, 교체 HUD 및 미지정·추상 HUD의 설정별 실행 확인은 이번 검증 범위에 포함하지 않는다.

## 이후 검증 방식 — 사용자 결정

기능 구현과 필요한 빌드 확인을 마친 뒤 **플레이 테스트 창 하나만 열고 사용자의 직접 테스트 결과를 기다린다.** 자동화 테스트를 여러 종류로 추가·반복하는 작업을 기본 절차로 삼지 않는다. 이번 검증은 사용자 요청에 따라 여기서 종료했다.

실제 구조·전투·진압을 포함한 한 판이 에디터에서 정상 완료되기 전에는 쿠킹·패키징·패키지 플레이를 기본 검증 범위에 넣지 않는다. 이번 개발용 완료 목표의 왕복은 그 기준을 통과한 것으로 보지 않는다. 그 이후 패키징을 시작하며, 별도 명시 요청이 있으면 해당 범위를 따른다. 상위 `D:/MyProject/ProjectW/AGENTS.md`에도 같은 기준을 기록했다.
